Start here

one SDK object · one public API · a template that runs as-is

Import the pool module from dapp/ in the repository and you have the read path, every op builder and the relay client. Nothing needs a build step, a framework or a backend. docs/dapp-template/index.html is a one-file starting point that opens in a browser and runs.

import { makeConfidentialPoolUx } from './dapp/confidential-pool-ux.js';
import * as secp from '@noble/secp256k1';
import { keccak_256 as keccak256 } from '@noble/hashes/sha3';
import { sha256 } from '@noble/hashes/sha256';

const tacit = makeConfidentialPoolUx({ secp, keccak256, sha256, network: 'mainnet' });
const acct  = tacit.account(walletPriv);            // the derived Ethereum account: { address, priv }
const me    = tacit.identity(walletPriv);           // the confidential identity: { priv, pubHex, owner, secret }
const { notes, byAsset } = await tacit.balance(walletPriv);

Before your first op

  • One secp256k1 key is the identity. tacit.account(walletPriv) is the Ethereum account that sends your deposits and self-submitted settles. It is not the plain address of the same key. Fund it with a little ETH once; relayed ops need none.
  • Everything comes back from the key. tacit.recover({ walletPriv }) finds notes, farm and CDP positions, cBTC and stealth locks from chain data alone. Save the few records it cannot re-derive, such as a CDP position’s secrets, before you submit.
  • Rescan before a spend. The pool accepts every root it has ever had, so a membership path never expires. An op carries one spendRoot, so take every input’s path from the same scan.
  • One key per process. A scan returns every note sealed to the key, including notes another process made.
  • A first integration: wrap, settle the wrap, send to yourself, unwrap. That covers a deposit, a proof, a spend and an exit.

The model

one settle function · one immutable program key

  • Your balance is a set of notes. A note is (asset, value, blinding, owner); only its Pedersen commitment C = value·H + blinding·G is public.
  • The pool stores leaves, keccak(assetId ‖ Cx ‖ Cy ‖ owner), in an append-only Merkle tree.
  • Spending a note publishes a nullifier, never the leaf. A second spend reverts.
  • Every change goes through ConfidentialPool.settle(publicValues, proofBytes, memos), which verifies one SP1 Groth16 proof against the pool’s immutable PROGRAM_VKEY. wrap() is the one exception: a plain payable call that escrows funds.
  • A memo per created leaf carries the note’s opening, encrypted to its owner. Notes a wallet mints for itself also re-derive from its key.
  • The relay proves and settles an op for a relay fee paid out of that op. It never receives the wallet key or a note’s blinding.

The pool has no proxy, no upgrade path, no pause switch and no key over escrow, exits or payouts. It is the root of the V1 lineage. Its lineage steward, the ops multisig, can deploy a successor once; that closes this pool to new value while every exit stays open. pool.successor() reads zero.

Four things that surprise everyone

  • You cannot send a note straight to someone else. A note’s owner is keccak(nk ‖ dom), a hash, so a note minted to another person’s key could never be spent. Pay others with a stealth lock that they claim.
  • Values are 8-decimal in-system units, not wei. The value is amount / unitScale and must divide exactly; ETH, TAC, cBTC and cUSD use 1e10.
  • Bitcoin value arrives two ways. A bridge burn is minted once on Ethereum, or a note bound to this pool is spent directly in the fast lane. Both wait for reflection, which folds a Bitcoin block once it is 24 blocks deep, about four hours.
  • A wrap is two steps. The deposit is a plain transaction; a proof turns it into a note.

Path 01

ETH and tokens · wrap, send, exit

ETH 0x3cba71e1…6f34 · any registered ERC-20 · no Bitcoin involved

// 1. deposit: your own transaction, no proof
const w = await tacit.wrap({ walletPriv, amountWei: 10n ** 16n, ticker: 'cETH' });
// 2. turn the deposit into a note: one relayed proof, once the wrap is mined
await tacit.submitWrapSettle({ built: w });

// send to yourself (split or merge), pay someone else, exit
const fee = await tacit.quoteTransferFee(5_000_000n, 'cETH');
await tacit.transfer({ walletPriv, notes, recipientPubHex: me.pubHex, amount: 5_000_000n, fee });
await tacit.stealthSend({ walletPriv, notes, recipientPubHex, amount: 5_000_000n });
await tacit.unwrap({ note: notes[0], walletPriv, recipient: '0x…' });
  • Record the wrap index. tacit.wrap takes the next unused index. If the settle step fails, buildWrap with the same index rebuilds the same deposit. The escrow has no deadline, and wrapping again would deposit twice.
  • One transaction. wrapAndSend wraps and settles together and splits the deposit into an amount and change. To pay the relay inside a plain deposit, send it through WrapTipForwarder with the tip GET /confidential/quote recommends.
  • Paying someone else. stealthSend locks to a one-time key derived from their tacit1… address, and they claim it. The sender can refund after the lock’s deadline, about 90 days by default. A .wei, .gwei or .eth name can carry that address in its finance.tacit text record; confidential-names.js resolves and publishes it.
  • Exiting. unwrap pays a whole note out; sendUnwrap pays an exact amount and keeps the change private. Confirm an exit by the recipient’s balance or the settle receipt, not by the relay’s status. The pool has no withdraw() and no receive(). An exit is the unwrap op, a proof that settle applies. A direct call or a plain transfer to the pool address reverts and moves nothing.

Exiting straight to Base or Robinhood Chain

ConfidentialRouter unwraps into a deterministic escrow (escrowAddressFor(recipe)) and makes the L2 deposit from it. exitAndExecute(recipe, publicValues, proofBytes, memos) does it in one transaction you send. Otherwise a relayed unwrap funds the escrow and anyone calls activateExit(recipe). reclaimExit returns the funds if the deposit never fires. Base uses L1StandardBridge. Robinhood Chain, an Arbitrum Orbit chain, uses a retryable ticket.

Two rules for the L2 exit
  • Arbitrum aliases contract callers: use createRetryableTicket naming the recipient, and check eth_getCode on any refund address.
  • exitAndExecute needs about 2,000,000 gas and activateExit 800,000 to 1,000,000. Cap a dry run at the limit you will send.

Path 02

Trading and liquidity

one (asset pair, fee tier) is one pool · public reserves · public or private trades · anyone can found one

One pool, two doors

A pool’s reserves and its share total live in one place, pools(poolId). A swap or a liquidity position can reach them in the clear, as an ordinary transaction with no proof, or privately, as a note and a proof. Both move the same reserves, so liquidity is never split.

  • Public swaps wait for nothing. The swap clears against the live reserves inside its own transaction, so it can sit in one all-or-nothing transaction with other calls: a route through another pool, an order split across two pools, or one of ConfidentialRouter’s zaps (zapETHIntoLP, zapTokenIntoShieldedLP, zapETHIntoFarm).
  • Private swaps clear at the live reserves. The proof names the reserves it was built against, and the pool takes it only while they are still the live ones. If another trade lands first, the settle is refused, nothing is spent, and the app builds a fresh quote. A private swap hides which note was spent and who holds the output. A lone one still moves the reserves by its own amounts.
  • One liquidity. Public shares (lpShares) and LP-share notes count in the same totalShares. shieldShares turns a public position into a note in place, and OP_LP_ADD and OP_WRAP_LP open one privately.
  • Yield. On a pool without a protocol-fee switch, a swap’s fee stays in the reserves, so each share’s claim grows with every swap, public or private. A private position earns from public trading and the reverse, and can bond into a farm to earn TAC.
  • Bitcoin in the same pool. cBTC (locked BTC), TAC and other Tacit tokens, ETH (tETH) and any registered ERC-20 are notes of one format. Bitcoin moves in and out by proof, never by a signer (03); ETH and tokens wrap and unwrap (01).

Path 03

Bridge · Bitcoin and Ethereum

TAC, tETH, cBTC and cUSD ride one bridge · REFLECTION_CONFIRMATIONS = 24

Every canonical asset bridges the same way; only the asset id differs. tETH is native ETH under its Bitcoin-side id, so a bridged tETH note and a wrapped cETH note are one asset. GET /reflection/status shows the Bitcoin height reflection has attested.

Bitcoin to Ethereum

Bitcoin: bridge burn (0x2B)→reflection folds it→settle: OP_BRIDGE_MINT→note on Ethereum
const b = await tacit.bridgeBurnToPool({
  prims, note: { txid, vout, sats, asset, value, blinding }, notePriv,
  fee: 0n,                                     // or a ladder fee taken from the minted note
  dest: { owner: destOwner },
  deriveDestBlinding: (nu) => deriveBridgeMintBlinding({ privkey: priv, nullifier: nu }),
  isSpendable: (u) => isPlainSats(u),
});
// once reflection has folded b's block:
await tacit.bridgeMint({ ...b.mintArgs, recovery });
  • The burn is a standard commit and reveal that any node relays. Derive the destination blinding with deriveBridgeMintBlinding (bridge-mint-recovery.js) so the minted note comes back from the key.
  • The mint is relayed and can pay its relay fee from the minted note. At fee 0 it relays within the free daily budget, so a holder with no ETH can finish.
  • Check the note first. A note is tracked when its history is inside reflection’s tree; GET /reflection/note-witness?leaf= finds it. A note whose history reflection never folded bridges by a burn-deposit instead. That takes a provenance bundle registered at POST /reflection/burndep and a burn that goes straight to a miner because it is non-standard (makeBurnDepositBroadcaster submits it to MARA Slipstream). A standard burn of an untracked note folds nothing.

Ethereum to Bitcoin

settle: OP_BRIDGE_BURN→Bitcoin: T_CROSSOUT_MINT (0x65)→reflection folds it→note on Bitcoin
const r = await tacit.crossOut({ walletPriv, notes, amount, destOwner, destChain: 1 });
// r carries the claim id read back from CrossOutRecorded (claimIdVerified) and the settle's block
await broadcast.completeCrossOutOnBitcoin({ ...r, ...r.crossOuts[0] });   // dapp/crossout-broadcast.js
  • Exact amount. The notes must sum to exactly amount + fee. A bridge burn has no change output. destOwner is the recipient’s x-only Taproot key.
  • Wait for coverage. completeCrossOutOnBitcoin broadcasts only once GET /reflection/eth-state/covers says the settle’s block is covered, and only with a verified claim id. tools/build-crossout-mint.mjs builds the same pair for review by hand.
  • Credit. GET /crossout/minted?asset=&claim=&txid= reports whether a mint was credited.
A wrong cross-out mint fails silently
  • The reveal’s output 0 must be a P2TR output paying destOwner. Anything else is not a member, and nothing reverts.
  • Build from the claim id the pool emitted, never from a prediction.
  • The guest checks a mint once, when it scans it, so a mint broadcast before its block is covered never folds.

The fast lane

Once reflected, a Bitcoin note bound to this pool (T_CXFER_BOUND, 0x39, carrying the pool’s chain binding) can be spent on Ethereum directly, with no burn and mint: tacit.fastlaneExit. The settle proves the note’s membership in the attested Bitcoin tree, its absence from the reflected spent set and a BIP-340 signature by its key. It records the spend, so the note cannot also be spent on Bitcoin. buildTacMigration (burn-deposit-bitcoin.js) moves a reflected note into the bound form in one Bitcoin transaction.

mainnet250,000 TAC spent in the fast lane, then unwrapped to an ERC-20 balance · a tETH fast-lane spend

Notes on Bitcoin

  • Split or merge a Bitcoin note with a confidential transfer (T_CXFER). Each output needs its own P2TR key, which becomes that note’s spend key.
  • A note that came through reflection nullifies under btc_note_leaf(asset, cx, cy, authKey), keyed by its own Taproot key. A burn that declares the wrong nullifier never folds, so check it against the note’s live key before broadcasting.

Path 04

cBTC and cUSD

cBTC 0x62a20d98…79c8 · cUSD 0x8f4490dd…679d · minted against self-custody Bitcoin

  1. Lock. Send BTC to a self-custody output whose transaction carries the lock envelope (T_CBTC_LOCK, cbtc-lock.js). Pick the funding input first: the cBTC note’s blinding derives from your key and that funding outpoint, which is how recovery finds it.
  2. Escrow. Post a bond of wstETH worth requiredEscrow(vBtc), 1.5 times the lock today, through CbtcEscrowHelper: postEscrowWithETH(outpoint) stakes raw ETH (about 320,000 gas), postEscrowWithPermit uses a wstETH permit, and reclaimEscrow returns your share. Anyone may fund a lock.
  3. Wait for reflection to fold the lock; pool.cbtcLockVBtc(outpoint) then reads its value.
  4. Mint. tacit.mintCbtc({ walletPriv, outpoint, vBtc, blinding }), relayed and free. The note is a bearer note. A lock mints once; a second mint reverts CbtcLockMismatch.

Borrowing cUSD

Open a position with tacit.defiActions(walletPriv).openCdp. A mint needs 150% collateral, and a position can be liquidated below 130%. cUSD has 8 decimals.

  • Rate snapshot. Pass the engine’s live rate(), which is 1e27 while the stability fee is dormant. A value outside [RAY, rate()] reverts BadSnapshot.
  • Save the position secrets first. The position owner key, the debt blinding and the debt note’s nk exist nowhere else.
  • Mint at fee 0. A relay fee taken from the debt note leaves you less cUSD than the position owes, so openCdp refuses one unless you pass acknowledgeFeeShortfall: true.
  • Close by burning debt notes worth at least the debt (an excess is burned, not refunded), with the position’s path from tacit.cdpPositionTree() and a fresh blinding and nk for each released leg.

The public ERC-20 forms, tacBTC and tacUSD, come from unwrapping a note, and a mint and an unwrap can share one settle. ConfidentialRouter.zapETHToCanonicalCdpMint buys collateral through zRouter, wraps it and settles your CDP-mint proof in one transaction. CbtcEscrowHelper.postEscrowWithETHAndSettle posts the escrow and settles a self-proved cBTC mint and CDP open together.

Path 05

Farms · earn TAC

FarmManager 0x000031C47Cb61faB1CE2790a69625FABB71EDE24 · reward wTAC · epoch 1 ends 2026-12-19

The three pools above earn TAC while their LP shares are bonded: TAC/cETH (weight 50), cETH/cUSD (30) and cETH/cBTC (20). Epoch 1 streams 99,700 TAC over 90 days, to unix 1797712559. Rewards are wTAC notes, and each wTAC redeems for one TAC. Read the live program from GET /farm/program?network=mainnet or tacit.farmProgram(), and its checks from GET /farm/health. Weights are governed, so read them instead of hardcoding them.

await tacit.lpBond({ walletPriv, controller: farm.manager, aNote, bNote, feeBps: 30, selfRelay: true });
const positions = await tacit.farmPositions({ walletPriv });
await tacit.farmHarvest({ walletPriv, position: positions[0] });   // harvest first
await tacit.farmUnbond({ walletPriv, position: positions[0] });
  • One step in. lpBond adds liquidity and bonds in one settle. It has no fee leg, so send it with selfRelay: true. farmBond bonds an LP note you already hold.
  • Recovery. The position key derives from your wallet key and the bonded note, so farmPositions finds it again.
  • Harvest before you unbond. A harvest re-stamps the position, and unbonding forfeits whatever was not harvested.
  • Redeeming. Unwrap the wTAC note, then call WrappedTac.withdraw(amount, to) for TAC. farmRedeem drives both steps.
  • Governance. The ops multisig re-weights through a 7-day public queue, at most ±25% per change and one change per 30 days. The rate can only be kept or raised, and the end only moved later. It cannot touch a position.

Path 06

TAC ERC-20 · list it in DeFi

0xA1313eb9f3A445606D9583bcAc3ebeB56a858279 · 18 decimals · minted only by the pool

This path is for a DEX, an aggregator, a lending market, a wallet or a market-data site. TAC was etched once on Bitcoin with a supply of 21,000,000 and no mint authority. Path 07

TAC airdrop

TacAirdrop 0x4b4cb98D0C836c2783Ac46f0078b904dab533AE8 · 8,652 recipients · claim by 2026-12-20 21:50 UTC

The airdrop is a Merkle claim of public TAC. claim(index, account, amount, proof) can be sent by anyone and always pays account, so a wallet can pay the network fee without being able to redirect the TAC. claimTo and claimAndShield need the eligible account itself.

const s = await tacit.tacAirdrop.status(address);   // fetches the proof, checks it against the root, reads the contract
// s.amountTac, s.claimByISO, s.reason: show 'error' as "could not check", never as "not eligible"
  • Offer claim and claimTo. The shield route’s final settle has not been run for this contract, so the client builds it only with allowUnproven: true.
  • People check and claim at tacit.finance/rewards: look up any address or .eth, .wei or .gwei name, claim from the account itself (to itself or to another address), then farm the TAC.
  • Proof files are at tacit.finance/airdrop/v1/proofs/<xx>.json. tacit.finance sends no CORS header, so a page on another origin reads the commit-pinned mirrors in PUBLIC_PROOF_HOSTS.
  • The guardian, the ops multisig, can pause claims and sweep the balance. It cannot change the root, the token or the deadline.

Path 08

One key, two chains

a Tacit key from the wallet a user already has, with nothing to back up

Every Tacit key is a secp256k1 key, so one key has both an Ethereum and a Bitcoin address. Tacit apps derive it from one fixed message the user signs: identityMessage({ netName }) in identity-message.js. The key is prfBytesToScalar(sha256(signature)) over the 65-byte signature, with v folded to 27 or 28. An EOA’s signature is deterministic, so reconnecting the same wallet gives the same key. Contract wallets are refused. A Bitcoin wallet can sign the same message instead; the app then signs twice and requires identical output. tacit.finance/kit/tacit-address-kit.js does the derivation and builds the tacit1… address in one dependency-free module.

The signature is the key

Anyone who gets it controls all of the user’s Tacit funds. Every Tacit app uses the same text, so a wallet cannot warn about the site. Ask for it only in an app the user trusts. Never send, log or store it, and zero it once the key is derived.

Proving and fees

every op except wrap() needs an SP1 proof · you choose who proves and who sends

  1. Hosted, the default. The relay proves on the Succinct network and sends settle(); confidential-relay.js polls the job for you.
  2. Proof only. mode: 'prove' returns the proof and you send settle() (tacit.submitSettle). selfRelay: true on an SDK call does both.
  3. Your own prover. Prove with your own Succinct account (self-prover.js, OPEN-RELAYER.md), and the witness never reaches the relay.
Fees
  • The relay fee is paid in the op’s own asset, from fee legs inside the op. The relay prices cETH, cUSDC, cUSDT, cUSD, cBTC and cTAC.
  • An op with a fee leg must clear the floor from GET /confidential/quote. Quote with tacit.quoteTransferFee or tacit.quoteOpFee. The program takes only fees on its two-significant-digit ladder.
  • Ops with no fee relay free within a daily budget: stealth and adaptor locks, wrap, cbtcmint, farmbond, cdptopup and a zero-fee bridgemint.
  • Pool founding and lpBond are sent from your own account.

What the relay sees. The witness of the op you hand it: the spent notes’ commitments, owners, paths and nullifier keys, the outputs, the public legs, the authorizing signature or kernel and the sealed memos. Never your wallet key or a note’s blinding. It can prove the op you authorized or decline it; it cannot redirect an output or raise the fee. For a swap it also sees the amounts.

TAC for gas and proofs

sign one order · a solver or prover is paid in TAC · both contracts are immutable

Gas in TAC. A wallet with no ETH swaps a token or enters a pool by signing one EIP-712 order (dapp/gas-relay.js: buildOrder, orderTypedData). The order authorizes exactly one call, bound by hash, once. TacitGasRelay pulls the input and the fee with the wallet’s permit (ERC-2612 for TAC and USDC, Permit2 for other tokens), makes the call, pays the output to recipient and pays the sender its fee in TAC or the token spent; if any step fails the whole order reverts and the wallet pays nothing. Post it with submitOrder(post, order), which calls POST /gas/order. feeFor sizes the fee and needsRelay says when the wallet’s ETH is short. The contract can call only the targets it was deployed with: zRouter, the ETH, TAC, TACD, TACE, USDC and USDT pool routers and ConfidentialRouter.

Proofs in TAC. A holder who wants a private wrap proved fast signs an Intent in TAC: a floor, a maximum and a ramp between them (dapp/proof-market.js: buildIntent, signIntent, signTacPermit, priceAt). A Tank (buildTank, signTank) is a session key with a cap and a per-order maximum, so later orders sign silently. Post an order with buildOrder to POST /market/order. A prover claims it on ProofMarket and fulfils it with the proof: the pool settles and the TAC is pulled in the same transaction, so a prover is paid only for a proof the pool accepts. Today the orders are wraps (wrapPublicValues).

Running one
  • Run a prover with node tools/community-runner.mjs prove or tools/proof-market-solver.mjs, and see community ops.
  • pool.settle is permissionless, so a prover should submit privately: a copier in the mempool can settle the same proof first.
  • Both boards list orders at /gas/orders and /market/orders on the public API.

Gotchas

  • Output 0 is the cross-out note. A Bitcoin mint reveal pays the declared key as a P2TR output at output 0, or it never folds.
  • Wait for coverage. Broadcast a cross-out mint only after /reflection/eth-state/covers says yes, built from the claim id the pool emitted.
  • The nullifier follows the note’s history. A reflected Bitcoin note nullifies under btc_note_leaf with its own Taproot key.
  • Four hours of depth. Nothing within 24 blocks of the Bitcoin tip is folded. Say so in the interface, not only in a retry loop.
  • Whole notes. A route and an LP removal spend their input whole.
  • One key per process. Two processes on one key pick each other’s notes as inputs.
  • Send from your own account. Never sign from a key the relay or a keeper uses. Two senders on one nonce sequence stall each other.
  • Confirm exits by balance. An unwrap can report settled from the relay’s acknowledgement. The recipient’s balance is the proof.
